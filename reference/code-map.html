Entry Point

__main__.py

sentinelgui/__main__.py MAIN

Purpose: The script that runs when you type python -m sentinelgui. Parses CLI arguments and wires everything together.

Key function: main()

ArgumentEffect
--simulateUse the built-in fault simulator instead of Arduino hardware
--port --baudSerial port settings for real hardware
--kioskFullscreen exhibition mode with enlarged UI
--scenario / -sWhich process to monitor (reactor, boiler, distillation, contact)
--configPath to custom GUI config JSON

Flow:

__main__.main()
  → AppController(scenario_id)   # app.py
  → controller.use_serial() | use_simulator()
  → MainWindow(controller)       # dashboard/main_window.py
  → controller.start()
  → window.run()                 # root.mainloop() — blocks until window closes
  → controller.stop()            # generates PDF report

Data Sources

acquisition.py

sentinelgui/acquisition.py SRC

Purpose: Reads sensor data from an Arduino over USB serial. Handles opening the port, reading CSV frames in a background thread, parsing them, and pushing parsed frames onto a thread-safe queue.

Libraries used: pyserial (lazy import — only loaded when hardware mode is activated)

Key class: SerialDataAcquisition

  • start() — Opens serial port, spawns reader thread
  • stop() — Closes port, joins thread
  • (background thread) — Calls readline(), splits by comma, converts to floats, pushes {"temperature": x, "flow_rate": y, "pressure": z} onto out_queue

Why lazy import? If running --simulate, pyserial is never imported. Zero dependency overhead in simulation mode.

Output: Raw dicts onto queue.Queue — same format as the simulator, so downstream code is source-agnostic.

simulator.py

sentinelgui/simulator.py SRC

Purpose: No-hardware data source for demos and development. Generates realistic readings with noise and on-demand fault injection.

Key class: FaultSimulator

  • inject(fault) — Start easing readings toward a fault signature
  • clear_fault() — Return toward nominal
  • next_frame() — Advance one tick (25% toward target + random noise) and return values
  • start() / stop() — Background thread that pushes frames at 1 Hz onto a queue

Fault signatures (reachable after ~15 ticks):

FaultTemperature →Flow Rate →Pressure →
blockagenominallowhigh
pump_failurenominal~0low
cavitationnominalnominallow + sin oscillation
foulingrising slowlymildly reducednominal
thermal_runawaysteep risenominalnominal
cooling_failurerisingnominalnominal

process_engine.py

sentinelgui/process_engine.py SRC

Purpose: Converts raw sensor frames into Reading objects. The Arduino already sends engineering units, so this is mostly pass-through with a calibration hook.

Key functions:

  • to_engineering(raw) — Apply value * scale + offset per sensor; returns None if any result is non-finite (NaN/infinity)
  • build_reading(raw, seq, source, now) — Creates a Reading object; returns None on conversion failure

Calibration: CALIBRATION = {"temperature": (1.0, 0.0), "flow_rate": (1.0, 0.0), "pressure": (1.0, 0.0)} — identity by default. Edit to add scaling without changing firmware.

Business Logic

reading_window.py

sentinelgui/reading_window.py LOGIC

Purpose: A bounded, time-ordered buffer of the most recent 300 readings. Used for trend slope and variance calculations.

Key class: ReadingWindow

  • append(reading) — Add a reading (oldest falls off when buffer is full)
  • series(sensor) — Return all values for a sensor as a list
  • slope(sensor, n=10) — Average per-sample rate of change over the last N readings: (last - first) / (count - 1)
  • variance(sensor, n=10) — Population variance over the last N readings (used for cavitation detection)

Implementation: Backed by collections.deque(maxlen=300) — O(1) append, bounded memory.

alarm_manager.py

sentinelgui/alarm_manager.py LOGIC

Purpose: Classifies each sensor value into normal / warning / critical zones. Applies debounce to prevent flickering alarms.

Key class: AlarmManager

  • evaluate(reading) → list of state changes (alarms raised or cleared)
  • Debounce: a value must be out of range for 2 consecutive readings before an alarm fires
  • .active → list of currently active alarms
  • .history → all alarms from this session

How zone_of works: Checks critical band first (if value < critical.min or > critical.max → critical). Then checks warning band. Otherwise normal. Bounds are inclusive.

fault_engine.py

sentinelgui/fault_engine.py LOGIC

Purpose: The heart of diagnosis. A rule-based classifier that checks 6 fault signatures in priority order (first match wins).

Key function: classify(reading, window, active) → FaultDiagnosis

Resolution order:

#FaultConditionConfidence
1Pump failureflow ≤ FLOW_NEAR_ZERO AND press ≤ PRESS_LOWhigh if both slopes ≤ 0
2Blockageflow < FLOW_LOW AND press > PRESS_HIGHhigh if flow down AND press up
3Cavitationpress < PRESS_LOW AND pressure variance > thresholdmedium (always)
4Thermal runawaytemp ≥ TEMP_CRITICALhigh if temp slope ≥ steep
5Cooling failuretemp > TEMP_WARN AND flow adequate (≥ FLOW_ADEQUATE)high if temp rising
6Foulingtemp > TEMP_WARN AND flow reduced (< FLOW_ADEQUATE)high if temp up AND flow down
7Undeterminedno signature matchedlow

Tuning: Global constants (FLOW_LOW, PRESS_HIGH, etc.) are overridden per scenario via set_tuning(). reset_tuning() restores reactor defaults. See scenario.py and config/scenarios/*.json.

react_agent.py

sentinelgui/react_agent.py LOGIC

Purpose: The Observe → Reason → Act loop. Ties together the alarm manager, reading window, and fault engine into one per-reading step.

Key class: ReActAgent

  • step(reading) → AgentResult — evaluates alarms, calls classify, builds stage health, generates trace
  • _stage_health(diagnosis) — colours mimic stages based on active alarms; dynamically maps pump/blower faults to the correct stage
  • request_ai(alarm, callback) — optional Gemini AI enrichment on a background thread (never blocks UI)

Output: AgentResult containing: new_alarms, cleared_alarms, diagnosis (FaultDiagnosis or None), stage_health dict, trace list of human-readable strings.

App Controller

app.py

sentinelgui/app.py APP

Purpose: The central coordinator. Owns the scenario, bands, window, alarms, agent, and data source. Runs the poll() loop on a timer. Handles scenario switching, serial fallback, fault injection, emergency shutdown, and report generation.

Key class: AppController

MethodWhat it does
use_simulator()Creates FaultSimulator with current scenario's nominal/targets
use_serial(port, baud)Creates SerialDataAcquisition
start()Starts the data source + a 100ms UI timer that calls poll()
stop()Generates PDF report, stops data source
poll()Drains the queue, builds readings, passes through agent pipeline, updates the view
inject_fault(fault)Injects a fault into the simulator (ignored in hardware mode)
clear_fault()Clears the active fault
switch_scenario(id)Reloads scenario JSON, resets bands, windows, alarms — keeps the dashboard running
emergency_stop()Latches SHUTDOWN state, sends STOP command over serial, generates report
_auto_recover_to_simulator()2 missed readings → transparently switches from serial to simulator

Dashboard — GUI Layer

The dashboard lives in sentinelgui/dashboard/ and uses customtkinter for all widgets. Every file imports customtkinter as ctk. Files derive from ctk.CTkFrame and are composed in main_window.py.

main_window.py

sentinelgui/dashboard/main_window.py GUI

Purpose: The root application window. Composes all panels (sensor cards, trend charts, mimic diagram, alarm panel, trace panel, fault log, AI panel) and the toolbar. Handles update(state) calls from AppController that refresh every widget.

Key features: Scenario dropdown, Inject Fault dropdown, Clear Fault button, Emergency Stop button, Record toggle, Kiosk mode (fullscreen, enlarged fonts, confirmation dialog for stop).

sensor_card.py

sentinelgui/dashboard/sensor_card.py GUI

Purpose: One card per sensor showing current value, label, unit, and zone colour (normal = green, warning = amber, critical = red). Uses ctk.CTkFrame with CTkLabel children. Calls configure(fg_color=...) to update colour on each reading.

trend_chart.py

sentinelgui/dashboard/trend_chart.py GUI

Purpose: Real-time line chart per sensor using Matplotlib embedded in CustomTkinter. Creates one matplotlib.figure.Figure per sensor, draws a rolling line of the last ~60 readings, colours the line by zone.

Key imports: from matplotlib.backends.backend_tkagg import FigureCanvasTkAgg, from matplotlib.figure import Figure.

Key method: update_chart(values) — appends a point, scrolls the x-axis, recolours lines.

mimic_diagram.py

sentinelgui/dashboard/mimic_diagram.py GUI

Purpose: Process flow diagram drawn on a Tk Canvas. Each stage is a rectangle; arrows connect consecutive stages. Stages are coloured by health (normal / warning / critical). Adapts dynamically to any scenario's stage list.

Key method: update_health(stage_health) — recolours each node based on its current zone.

alarm_panel.py

sentinelgui/dashboard/alarm_panel.py GUI

Purpose: Scrollable table of active and cleared alarms. Each row shows: timestamp, sensor, severity (coloured badge), value, limit breached. New alarms are prepended. Severity colouring: warning = amber background, critical = red background, cleared = grey.

trace_panel.py

sentinelgui/dashboard/trace_panel.py GUI

Purpose: Displays the agent's reasoning trace in Observe → Reason → Act format. Each entry shows: sensor values with zone labels, the diagnosis (fault name + confidence), and the action taken (alarm raised). Automatically scrolls to show the latest entry.

fault_log.py

sentinelgui/dashboard/fault_log.py GUI

Purpose: Persistent log of every fault diagnosed during the session. Shows timestamp, fault type, explanation, and confidence. Separate from alarms because one fault may span multiple readings (and thus multiple alarms).

ai_panel.py

sentinelgui/dashboard/ai_panel.py GUI

Purpose: Optional enrichment panel that sends the current alarm context to Google Gemini for a natural-language explanation. Shows a "Get AI Insight" button per alarm. Displays the AI response in a scrollable text area. Runs the API call on a background thread — UI never blocks.

theme.py

sentinelgui/dashboard/theme.py GUI

Purpose: Central colour palette and font sizes for the entire dashboard. All other dashboard files import from here rather than hardcoding colours. Makes global theme changes trivial. Defines: BG, PANEL, PANEL_LIGHT, MUTED, ZONE_COLORS, font() helper.

Output and Reporting

report.py

sentinelgui/report.py RPT

Purpose: Generates a one-page PDF summary at the end of a session (emergency stop or window close). Contains: scenario name, duration, readings processed, alarm counts by severity, fault counts, and a timeline table.

Library: fpdf2 — pure Python PDF generation.

Note: Uses ASCII-safe _s() helper because fpdf2's built-in Helvetica font doesn't support Unicode.

exhibition_doc.py

sentinelgui/exhibition_doc.py RPT

Purpose: Generates the 7-page exhibition handout PDF (sentinelgui_exhibition.pdf). Covers: system overview, sensor spec, fault catalog with chemistry explanations, multi-scenario config, command reference, architecture diagram.

exhibition_docx.py

sentinelgui/exhibition_docx.py RPT

Purpose: Word document version of the exhibition handout (sentinelgui_exhibition.docx). Same content as exhibition_doc.py but in DOCX format using python-docx.

data_logger.py

sentinelgui/data_logger.py RPT

Purpose: Records the reading stream to a timestamped CSV file. One row per reading with columns: timestamp, seq, source, temperature, flow_rate, pressure, alarms. Uses Python's built-in csv module — no pandas needed. If the file can't be written, the session enters an error state but monitoring continues.

Key class: DataLogger with start(), write(), stop().

Configuration

scenario.py

sentinelgui/scenario.py CFG

Purpose: Loads scenario JSON files from config/scenarios/. Each JSON defines: sensor labels, stage names, nominal values, fault targets, thresholds, fault tuning constants, and fault explanations.

Key class: Scenario — holds all parsed fields: name, stages, stage_sensor, nominal, fault_targets, thresholds, fault_tuning, fault_explanations.

Key functions: load_scenario(id) → Scenario, list_scenarios() → list of available scenario dicts.

thresholds.py

sentinelgui/thresholds.py CFG

Purpose: Two-band (warning/critical) threshold model. Validates nesting invariant: critical band must contain the warning band. Reuses SentinelCLI's project.check_reading() for zone evaluation so GUI and CLI agree on "in range".

Key function: zone_of(sensor, value, bands) → "normal" | "warning" | "critical".

Key class: ThresholdBand with critical dict and warning dict (each with min/max).

Bridge Modules

sentinelcli_bridge.py

sentinelgui/sentinelcli_bridge.py BRIDGE

Purpose: Reuses SentinelCLI's diagnose_alert() function and optional Gemini AI enrichment. Converts between Alarm (GUI model) and the CLI's alert dict format. AI calls use urllib to hit the Gemini REST API — no third-party SDK.

Key functions: alarm_to_cli_alert(alarm), ai_diagnose(alarm, client, timeout=10).

shutdown_controller.py

sentinelgui/shutdown_controller.py BRIDGE

Purpose: Manages the emergency shutdown sequence. Latches a safe UI state, sends a CMD:STOP command over serial (if available), and records the outcome. Integrates a countdown timer for automatic shutdown escalation.

Key class: ShutdownController — states: idle → latching → confirming → shutdown.
