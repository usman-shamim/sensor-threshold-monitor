1. customtkinter — Desktop GUI Framework

Why it was chosen Modern-looking, cross-platform GUI library built on tkinter. CustomTkinter provides themeable widgets (rounded corners, dark/light mode, colour accents) that look professional out of the box — no CSS, no web stack.

How it is used in SentinelGUI

The entire dashboard is built from ctk.CTkFrame, ctk.CTkLabel, ctk.CTkButton, ctk.CTkOptionMenu widgets. Every file in sentinelgui/dashboard/ (8 files) imports customtkinter as ctk:

  • main_window.py — Root window, composes all panels, handles scenario switching, kiosk mode
  • sensor_card.py — Individual value cards showing temperature / flow / pressure with zone colouring
  • alarm_panel.py — Scrollable alarm history table with severity colour coding
  • mimic_diagram.py — Process mimic diagram (nodes connected by arrows, coloured by zone)
  • trend_chart.py — Embedding Matplotlib charts inside a ctk.CTkFrame
  • trace_panel.py — Agent reasoning trace (Observe → Reason → Act log)
  • fault_log.py — Fault history log with diagnosis details
  • ai_panel.py — Optional AI enrichment panel

Key advantage: Pure Python, no web server, no JavaScript. Runs on any desktop with Python 3.14+ and one pip install.

2. pyserial — Serial Communication

Why it was chosen The only battle-tested Python serial library. Provides a clean, synchronous API over any serial port at any baud rate. Handles timeouts, parity, flow control — everything a real SCADA system needs.

How it is used

In acquisition.py, pyserial is imported lazily (only when hardware mode is requested). The SerialDataAcquisition class:

  1. Opens serial.Serial(port, baud, timeout=2.0)
  2. Spawns a background thread that calls readline() in a loop
  3. Parses CSV frames (temperature,flow_rate,pressure) from the Arduino
  4. Pushes each parsed frame onto a queue.Queue

Why lazy import? If the user runs --simulate, pyserial is never loaded at all. Zero overhead in demo mode; the library is purely optional.

Key advantage over alternatives (e.g., pySerial-asyncio): Blocking read on a background thread is simpler to reason about than async callbacks. A threaded queue is a well-understood pattern that any Python programmer can trace.

3. matplotlib — Real-time Trend Charts

Why it was chosen The most widely used plotting library in Python. Embedding Matplotlib figures inside tkinter/CustomTkinter via FigureCanvasTkAgg is a documented, stable pattern.

How it is used

trend_chart.py creates one matplotlib.figure.Figure per sensor. Each figure:

  • Renders a rolling line chart of the last ~60 readings
  • Colours the line by zone (normal = green, warning = amber, critical = red)
  • Updates on every new reading via canvas.draw_idle()

The canvas widget is embedded inside a ctk.CTkFrame alongside the sensor cards, so everything looks cohesive.

Key advantage over alternatives (plotly, bokeh): No browser, no web server, no JavaScript runtime. Matplotlib FigureCanvasTkAgg is a native tkinter widget — it lives inside the same window, redraws synchronously, and costs zero network overhead.

4. fpdf2 — PDF Report Generation

Why it was chosen Pure-Python PDF generation with no system dependencies (no LaTeX, no wkhtmltopdf). fpdf2 handles Unicode via built-in fonts and produces small, fast-to-generate PDFs.

How it is used

Two files use fpdf2:

  • report.py — Generates a one-page PDF summary on emergency stop or application shutdown. Contains: final readings, fault history, scenario name, timestamp.
  • exhibition_doc.py — Generates a 7+ page exhibition document covering: system architecture, sensor spec, fault catalog with chemistry explanations, command reference.

Key advantage over alternatives (ReportLab, WeasyPrint): fpdf2 is the simplest API — you call FPDF(), add_page(), set_font(), cell(). That's it. No stylesheets, no HTML parsing, no templating engine. For a 7-page document with tables and formatted text, it runs in under 2 seconds.
